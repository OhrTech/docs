**Our promise:** within `v1`, the API only adds: new operations, new optional fields, new values.
Anything else becomes `v2`, served alongside `v1`. The OpenAPI document's history is in the
[management-api repository](https://github.com/OhrTech/management-api/commits/main/openapi.json).

## 2026-11-04: your apps

- [Your apps](/management-api/guides/apps/): `GET` and `POST /v1/apps`, `GET` and `PATCH
  /v1/apps/{appId}`, the app's versions (`GET /v1/apps/{appId}/versions`), uploading an APK as a new
  version (`POST /v1/apps/{appId}/versions`, refused if it is another package), holding, offering or
  enforcing a version (`PATCH /v1/apps/{appId}/versions/{versionCode}`), the rollout
  (`GET /v1/apps/{appId}/rollout`) and a fleet's apps (`GET`, `PUT` and `DELETE
  /v1/fleets/{fleetId}/apps/…`).
- The new permission `ManageApps`, held by every member, lets the caller change apps. Seeing them
  needs `ManageApps` or `ViewDevices`.
- The [`ohr` command line](/management-api/cli/) is open source, for Linux, macOS and Windows.

## 2026-11-03: shell commands

- `POST /v1/devices/{deviceId}/shell` runs a [shell command](/management-api/guides/shell-commands/)
  on a device, as `adb shell` would. It needs `RemoteAdb`. The finished task's `shell` holds the
  exit code and output.
- Tasks have `createdBy`: the person or service account that created them.
- Devices have `shellCommands` (in the list, and under `capabilities`) and, in the list,
  `securityPatch`.

## 2026-11-03: corrections

- `os.securityPatch` is the Android security patch level the device runs now, as `YYYY-MM-DD`,
  reported at every check-in. It was the level the device's enrolment attested, as `YYYYMM`, which
  did not follow OS updates.
- `takeOver`, when opening a remote control session, is optional (default `false`).

## 2026-11-03: v1

The first public version:

- Devices and fleets: live status, details, installed apps, enrolments, check-in on demand, moving
  devices between fleets
- Settings: the catalog, reading, `PUT` and `PATCH` with validation, pushing again
- Messages and tasks
- Remote control, with the embeddable viewer and its `postMessage` interface
- Remote ADB sessions
- Sign-in: service accounts with permissions, device scope, network allowlist and embed sites; and
  the device code flow for people
