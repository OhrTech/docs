## Show a message

Needs `SendMessages`. The text (up to 1,000 characters) appears on the device's screen.

<Tabs syncKey="lang">
<TabItem label="curl">

```sh
curl https://api.ohrtech.net/v1/devices/dev_3swt6f457299btzpw1bxx4wf0q/messages \
  -H "Authorization: Bearer $OHR_TOKEN" -H "Content-Type: application/json" \
  -d '{"text": "Please bring this tablet to the front desk."}'
```

</TabItem>
<TabItem label="C#">

```csharp
var task = await api.ShowMessageAsync("dev_3swt6f457299btzpw1bxx4wf0q", new ShowMessageRequest { Text = "Please bring this tablet to the front desk." });
```

</TabItem>
</Tabs>

A device that is online shows it within seconds; one that is offline shows it when it next checks
in. To message a whole fleet, see the [broadcast](/management-api/recipes/broadcast-message/) recipe.

## Tasks

A message is delivered as a **task**, and so is everything else done on a device: OS and app
updates, OhrTech Agent updates, settings, [shell commands](/management-api/guides/shell-commands/).
The 201 response to a message is its task:

```json
{
  "taskId": "tsk_3b0wkr78p69s7tzaevqeef8pyh",
  "deviceId": "dev_3swt6f457299btzpw1bxx4wf0q",
  "taskClass": "ShowToast",
  "parameters": ["Please bring this tablet to the front desk."],
  "status": "pending",
  "priority": 1000,
  "createdAt": "2026-11-03T17:02:11Z",
  "modifiedAt": "2026-11-03T17:02:11Z",
  "createdBy": "service:help-desk",
  "messages": []
}
```

`status` goes `pending` → `running` → `success` (or `failed`, `cancelled`). `messages` holds what the
device reported along the way, and `result` its final answer. `createdBy` is the person or service
account that created the task; it is empty for the tasks OhrTech creates, such as updates. In C#,
`api.WaitForTaskAsync(task)` waits until the device has finished it.

| Call | |
|---|---|
| `GET /v1/devices/{deviceId}/tasks?limit=50&before={taskId}` | A device's tasks, newest first; page with `before` set to the last `taskId` you have |
| `GET /v1/devices/{deviceId}/tasks/{taskId}` | One task |
| `POST /v1/devices/{deviceId}/tasks` | Create a task: `{"taskClass": "ShowToast", "parameters": ["…"]}` |

Reading tasks needs `ViewDevices`, creating them `SendMessages`. Through `POST .../tasks` you can create
`ShowToast` (the same as a message); shell commands have
[their own call](/management-api/guides/shell-commands/), and OhrTech creates the rest. Download links
inside update tasks have their signature replaced with `REDACTED`.
