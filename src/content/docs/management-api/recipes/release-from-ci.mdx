Build the APK, upload it as the app's new version, enforce it, and wait until the devices run it.
The pipeline goes red if a device fails to install the update.

**Needs:** the app [added once](/management-api/guides/apps/#add-an-app) and assigned to its
fleets, and a service account with `ManageApps`, its token stored as the pipeline secret
`OHR_TOKEN`.

<Tabs syncKey="ci">
<TabItem label="GitHub Actions">

```yaml
name: Release
on:
  push:
    branches: [release]

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-java@v5
        with:
          distribution: temurin
          java-version: 21
      - name: Build
        run: ./gradlew assembleRelease
        # signing configured in build.gradle from your keystore secrets

      - name: Install ohr
        run: curl -fsSL https://github.com/OhrTech/ohr-cli/releases/latest/download/install.sh | sh

      - name: Release to the devices
        env:
          OHR_TOKEN: ${{ secrets.OHR_TOKEN }}
        run: >
          ohr apps upload com.example.kiosk app/build/outputs/apk/release/app-release.apk
          --enforce --skip-duplicate --wait --timeout 20m
```

</TabItem>
<TabItem label="GitLab CI">

```yaml
release:
  stage: deploy
  rules:
    - if: $CI_COMMIT_BRANCH == "release"
  script:
    - ./gradlew assembleRelease
    - curl -fsSL https://github.com/OhrTech/ohr-cli/releases/latest/download/install.sh | sh
    - ~/.local/bin/ohr apps upload com.example.kiosk app/build/outputs/apk/release/app-release.apk
      --enforce --skip-duplicate --wait --timeout 20m
  # OHR_TOKEN: a masked CI/CD variable
```

## How it works

- **The right app, or nothing.** The upload names the app (`com.example.kiosk`), and the API refuses
  an APK of any other package, so a misconfigured build can't release something else. If several of
  your apps share the package, flavours for different fleets, name the app by its id
  (`ohr apps upload 12 …`, one step per flavour): a package that fits more than one app fails
  instead of guessing.
- **Each build must be newer.** The API refuses a version code that isn't higher than every version
  already uploaded, and an APK signed with another key. `--skip-duplicate` makes a re-run of the
  same build succeed instead of failing: the version is already there.
- **`--wait`** follows the rollout until every online device runs the new version (exit 0), or one
  reports it couldn't install it (exit 1, with the device's reason). After `--timeout` it gives up
  with exit 9; the rollout carries on. Offline devices install the version when they next connect.

## Make it yours

- **Stage it.** Upload with `--available` instead of `--enforce`, or assign the app to a small
  test fleet first, then enforce the same version for everyone with
  `ohr apps release com.example.kiosk 240`.
- **Pin the tool.** `OHR_VERSION=1.0.0` before `sh` in the install step installs that release
  instead of the latest.
- **Without the tool.** The same from C#: `await api.UploadApkAsync(12, path, state: "enforced")`,
  then `await api.WaitForRolloutAsync(12)`. See [your apps](/management-api/guides/apps/).
