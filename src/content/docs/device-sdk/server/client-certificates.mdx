Your app on the device can present a client certificate whose key never leaves the device's TEE
(see [client certificates](/device-sdk/guides/certificates/) for the app's side). This page sets
it up and configures your servers to require it.

## How it fits together

- Your organisation has an **issuing CA**. OhrTech makes it and keeps its key; OhrTech's servers
  use it only to certify keys a device has attested.
- OhrTech certifies the issuing CA under the **OhrTech Device Identity Root**. You certify the same
  subject and key under **your own client root**, by signing its CSR.
- A **fleet** gives an app the issuing CA (and, if you want, private CAs to trust and PKCS#12
  certificates from your PKI).
- The app asks for a certificate. OhrTech checks the key's attestation and issues a leaf that names
  the device, the app and the package, valid for `leafDays`.
- Your server trusts your client root, and reads the device from the certificate.

The calls here are in the Management API; the .NET SDK doesn't have them yet, so the samples use
curl. The issuing CA calls need `EditSettings` in the organisation.

## Create an issuing CA

```sh
curl https://api.ohrtech.net/v1/orgs/org_4b60p9zf168jxsyx98w8wstk29/issuing-cas \
  -H "Authorization: Bearer $OHR_TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "Stores", "leafDays": 90}' > issuing-ca.json
```

| Field | |
|---|---|
| `name` | 1 to 100 characters, your name for it. It goes into the CA's subject. |
| `leafDays` | How long the certificates it issues are valid: 1 to 825 days, default 90. |

The answer (201):

```json
{
  "issuingCaId": "ica_5q8w2x4z6c9v1b3n7m0k2j4h6g",
  "orgId": "org_4b60p9zf168jxsyx98w8wstk29",
  "name": "Stores",
  "subject": "O=Example Corp, OU=OhrTech device identity, CN=Example Corp Stores Issuing CA",
  "leafDays": 90,
  "createdAt": "2026-11-08T06:21:47.416859Z",
  "revokedAt": null,
  "csrPem": "-----BEGIN CERTIFICATE REQUEST-----\n…",
  "ohrTechCertificatePem": "-----BEGIN CERTIFICATE-----\n…",
  "ohrTechChainPem": "-----BEGIN CERTIFICATE-----\n…",
  "orgCertificatePem": null,
  "orgChainPem": null,
  "issued": 0
}
```

The subject is `O=` your organisation's name, `OU=OhrTech device identity`, `CN=` your
organisation's name, the CA's name and "Issuing CA". The key is EC P-256. `ohrTechCertificatePem` is
OhrTech's certificate for it, valid for five years, and `ohrTechChainPem` is OhrTech Device Identity
Intermediate 1 and the root. `issued` counts the certificates it has issued.
`GET /v1/orgs/{orgId}/issuing-cas` lists your organisation's issuing CAs, newest first.

## Sign it with your client root

The CSR asks for a CA certificate: `CA:TRUE` with a path length of 0, key usage `keyCertSign`,
`cRLSign` and `digitalSignature`, extended key usage `clientAuth`. Sign it with your client root
and keep those extensions. With OpenSSL:

```sh
jq -r .csrPem issuing-ca.json > issuing-ca.csr

# Only if you have no client root yet: a new one, P-256, valid for 10 years. Keep its key offline.
openssl req -x509 -new -newkey ec -pkeyopt ec_paramgen_curve:P-256 -nodes \
  -keyout client-root.key -out client-root.pem -days 3650 \
  -subj "/O=Example Corp/CN=Example Corp Client Root" \
  -addext "basicConstraints=critical,CA:TRUE" -addext "keyUsage=critical,keyCertSign,cRLSign"

cat > issuing-ca.ext <<'EOF'
basicConstraints = critical, CA:TRUE, pathlen:0
keyUsage = critical, keyCertSign, cRLSign, digitalSignature
extendedKeyUsage = clientAuth
subjectKeyIdentifier = hash
authorityKeyIdentifier = keyid:always
EOF
openssl x509 -req -in issuing-ca.csr -CA client-root.pem -CAkey client-root.key \
  -days 1825 -sha256 -extfile issuing-ca.ext -out issuing-ca.pem

openssl verify -CAfile client-root.pem issuing-ca.pem    # issuing-ca.pem: OK
```

`openssl x509 -req` keeps the CSR's subject, which must stay as it is: the certificates the CA
issues name that subject as their issuer. Give it at least as long as you will use the issuing CA:
`-days 1825` matches OhrTech's five years.

If an intermediate of yours signs it rather than the root, use the intermediate's certificate and
key in `-CA` and `-CAkey`; the intermediate needs a path length of at least 1.

## Upload your certificate

```sh
jq -n --rawfile cert issuing-ca.pem --rawfile chain client-root.pem \
  '{certificatePem: $cert, chainPem: $chain}' |
curl -X PUT https://api.ohrtech.net/v1/orgs/org_4b60p9zf168jxsyx98w8wstk29/issuing-cas/ica_5q8w2x4z6c9v1b3n7m0k2j4h6g/org-certificate \
  -H "Authorization: Bearer $OHR_TOKEN" -H "Content-Type: application/json" -d @-
```

| Field | |
|---|---|
| `certificatePem` | The CA certificate your root issued from the CSR. |
| `chainPem` | Its issuers, up to and including your self-signed root: with an intermediate, the intermediate and the root. |

The API checks that the certificate is for the issuing CA's key, that it is a CA certificate, and
that it verifies to the self-signed root at the end of `chainPem`. If not, it answers 400 with what
is wrong, for example "the certificate is not for this issuing CA's key (sign its CSR)". The answer
is the issuing CA, now with `orgCertificatePem` and `orgChainPem`.

Certificates issued from then on carry both paths: through your root and through OhrTech's. Those
issued before carry only OhrTech's, until the app renews them. To replace your certificate (before
it expires, say), upload a new one the same way.

## Give an app the issuing CA

A fleet's setting gives each app its certificates:

```sh
curl -X PUT https://api.ohrtech.net/v1/fleets/flt_2dn47a2xa58j1txv8m28spkmyb/apps/app_7h2m9q4x1c8v3k5n6p0r2s4t6w/certificates \
  -H "Authorization: Bearer $OHR_TOKEN" -H "Content-Type: application/json" \
  -d '{"issuingCaId": "ica_5q8w2x4z6c9v1b3n7m0k2j4h6g"}'
```

| Field | |
|---|---|
| `issuingCaId` | One of your organisation's issuing CAs, not revoked. Null: the app gets no device-made certificates. |
| `trust` | Private CAs (PEM) the app trusts for your servers, besides the system's. Up to 20. |
| `imported` | Client certificates from your PKI, up to 10: `{"alias", "pkcs12", "password"}`, the PKCS#12 base64, at most 64 KB. To keep one already stored, send its alias with `"pkcs12": "*"`. |

With private CAs and a certificate from your PKI as well:

```sh
jq -n --arg p12 "$(base64 -w0 corp.p12)" --rawfile ca private-ca.pem \
  '{issuingCaId: "ica_5q8w2x4z6c9v1b3n7m0k2j4h6g", trust: [$ca],
    imported: [{alias: "corp", pkcs12: $p12, password: "s3cret"}]}' |
curl -X PUT https://api.ohrtech.net/v1/fleets/flt_2dn47a2xa58j1txv8m28spkmyb/apps/app_7h2m9q4x1c8v3k5n6p0r2s4t6w/certificates \
  -H "Authorization: Bearer $OHR_TOKEN" -H "Content-Type: application/json" -d @-
```

- A `PUT` replaces everything this fleet sets for the app. Leave a field out to drop it.
- The API checks every PEM, and that each PKCS#12 opens with its password and holds a private key
  (400 "Bad certificates" with the reason otherwise). It stores the PKCS#12 and its password
  sealed; it opens them only for the device, which hands them to that app alone.
- Fleets below inherit an app's certificates from the nearest fleet above that sets them. A fleet
  that sets them replaces them for that app, as a whole.
- `GET` on the same path shows what the fleet sets (`own`), what applies (`applies`) and the fleet
  it comes from (`inheritedFrom`), with the PKCS#12 and password shown as `*`; it needs
  `ViewSettings`. `DELETE` stops this fleet setting them, so the fleet above applies again. `PUT`
  and `DELETE` need `EditSettings`.
- The API sends the change to the fleet's devices at once, and the app hears of it (`changes`).

## Stop trusting

There is no per-certificate revocation list in this version. To stop certificates:

- **Revoke the issuing CA:** `POST /v1/orgs/{orgId}/issuing-cas/{issuingCaId}/revoke`. It issues no
  new certificates from then on: apps on fleets that still name it get `OhrException.Refused`, and
  no fleet can be given it. Certificates it already issued stay valid until they expire, `leafDays`
  after they were issued.
- **Keep `leafDays` short** if you need to cut devices off quickly: with 30 days, a revoked issuing
  CA's certificates are all gone within 30 days. `leafDays` is set when you create the issuing CA.
- **Refuse a device yourself:** your server reads the device id from each certificate (below) and
  can turn away the ones you no longer want.

To move devices to a new issuing CA, create it, sign and upload it, give it to the fleet, and
revoke the old one. Apps get certificates from the new one when they next call `request`, or when
`renewIfDue` finds the old one due.

## Which root to trust

| Trust | Accepts |
|---|---|
| Your client root | Certificates of your organisation's issuing CAs only. Use this. |
| The OhrTech Device Identity Root | A certificate of any OhrTech device, of any organisation, with the app and package it names. Trust it only if you then check the app id (`urn:ohrtech:app:`) or the device id against your own. |

The OhrTech Device Identity Root is public, no sign-in:

```sh
curl https://api.ohrtech.net/v1/device-identity/root -o ohrtech-device-identity-root.pem
openssl x509 -in ohrtech-device-identity-root.pem -noout -fingerprint -sha256
# sha256 Fingerprint=D5:BB:04:3D:F1:F8:0F:7C:6E:5C:D5:8B:52:B7:68:AB:B7:1C:9F:6E:10:C2:35:62:DB:26:D0:0A:F4:44:CF:8A
```

## Configure your server

Whatever the server, three things matter:

- **Trust your client root** (or the OhrTech root) for client certificates, and only that.
- **List it in the certificate request.** The app sends the path to the root the server names; with
  none named, it sends the path through your root. A server that names only the OhrTech root gets
  the OhrTech path.
- **Allow the chain's depth.** Through your root directly: the leaf, the issuing CA, the root. Through
  OhrTech's: one more, OhrTech Device Identity Intermediate 1.

<Tabs>
<TabItem label="nginx">

```nginx
server {
    listen 443 ssl;
    ssl_certificate         /etc/nginx/tls/server.pem;
    ssl_certificate_key     /etc/nginx/tls/server.key;

    ssl_client_certificate  /etc/nginx/tls/client-root.pem;   # trusted, and named in the request
    ssl_verify_client       on;
    ssl_verify_depth        2;

    location / {
        proxy_set_header X-Client-DN   $ssl_client_s_dn;            # CN=dev_…,O=Example Corp
        proxy_set_header X-Client-Cert $ssl_client_escaped_cert;    # the leaf, to read its URIs
        proxy_pass http://127.0.0.1:8080;
    }
}
```

`ssl_client_certificate` both trusts the file's CAs and names them in the certificate request;
`ssl_trusted_certificate` would trust them without naming them. nginx's default
`ssl_verify_depth 1` is enough when your root signed the issuing CA directly; `2` also covers an
intermediate of yours, or the OhrTech root.

</TabItem>
<TabItem label="Go">

```go
package main

import (
	"crypto/tls"
	"crypto/x509"
	"fmt"
	"log"
	"net/http"
	"os"
	"strings"
)

func main() {
	roots := x509.NewCertPool()
	pem, err := os.ReadFile("client-root.pem") // your client root (and/or the OhrTech Device Identity Root)
	if err != nil || !roots.AppendCertsFromPEM(pem) {
		log.Fatal("can't read client-root.pem")
	}
	srv := &http.Server{
		Addr: ":8443",
		TLSConfig: &tls.Config{
			ClientAuth: tls.RequireAndVerifyClientCert, // sends the CA names from ClientCAs
			ClientCAs:  roots,
		},
		Handler: http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			leaf := r.TLS.VerifiedChains[0][0]
			ids := map[string]string{}
			for _, u := range leaf.URIs { // urn:ohrtech:device:dev_…, urn:ohrtech:app:app_…, urn:ohrtech:package:…
				if rest, ok := strings.CutPrefix(u.String(), "urn:ohrtech:"); ok {
					kind, value, _ := strings.Cut(rest, ":")
					ids[kind] = value
				}
			}
			fmt.Fprintf(w, "device %s, app %s, package %s\n", ids["device"], ids["app"], ids["package"])
		}),
	}
	log.Fatal(srv.ListenAndServeTLS("server.pem", "server.key"))
}
```

Go's verifier finds a path through either copy of the issuing CA, so it accepts whichever path the
app sends, as long as it ends at a root in `ClientCAs`.

<TabItem label="ASP.NET Core">

```csharp nocheck
using System.Formats.Asn1;
using System.Net.Security;
using System.Security.Cryptography.X509Certificates;
using Microsoft.AspNetCore.Server.Kestrel.Https;

var builder = WebApplication.CreateBuilder(args);

var clientRoots = new X509Certificate2Collection();
clientRoots.ImportFromPemFile("client-root.pem"); // your client root (and/or the OhrTech Device Identity Root)
var serverCert = X509Certificate2.CreateFromPemFile("server.pem", "server.key");

builder.WebHost.ConfigureKestrel(kestrel => kestrel.ConfigureHttpsDefaults(https =>
{
    https.ClientCertificateMode = ClientCertificateMode.RequireCertificate;
    https.OnAuthenticate = (_, ssl) =>
    {
        // Check client certificates against your roots only (not the system's), for client authentication.
        var policy = new X509ChainPolicy
        {
            TrustMode = X509ChainTrustMode.CustomRootTrust,
            RevocationMode = X509RevocationMode.NoCheck,
        };
        policy.CustomTrustStore.AddRange(clientRoots);
        policy.ApplicationPolicy.Add(new("1.3.6.1.5.5.7.3.2"));
        ssl.CertificateChainPolicy = policy;
        // Name your roots in the certificate request, so the device sends the path to them.
        ssl.ServerCertificate = null;
        ssl.ServerCertificateContext = SslStreamCertificateContext.Create(serverCert, null, false,
            SslCertificateTrust.CreateForX509Collection(clientRoots, sendTrustInHandshake: true));
    };
}));

var app = builder.Build();
app.MapGet("/", (HttpContext http) =>
{
    var uris = OhrUris(http.Connection.ClientCertificate!);
    return $"device {uris.GetValueOrDefault("device")}, app {uris.GetValueOrDefault("app")}, package {uris.GetValueOrDefault("package")}\n";
});
app.Run("https://localhost:8444");

// urn:ohrtech:<kind>:<value> from the certificate's subject alternative names: device, app, package.
static Dictionary<string, string> OhrUris(X509Certificate2 cert)
{
    var found = new Dictionary<string, string>();
    if (cert.Extensions["2.5.29.17"] is not { } san) return found;
    var names = new AsnReader(san.RawData, AsnEncodingRules.DER).ReadSequence();
    var uriTag = new Asn1Tag(TagClass.ContextSpecific, 6);
    while (names.HasData)
    {
        if (names.PeekTag() != uriTag) { names.ReadEncodedValue(); continue; }
        var parts = names.ReadCharacterString(UniversalTagNumber.IA5String, uriTag).Split(':', 3);
        if (parts is ["urn", "ohrtech", var rest] && rest.Split(':', 2) is [var kind, var value]) found[kind] = value;
    }
    return found;
}
```

`sendTrustInHandshake: true` makes Kestrel name your roots in the certificate request. .NET's
`X509SubjectAlternativeNameExtension` reads DNS names and IP addresses only, hence the few lines of
ASN.1 for the URIs.

To try a server without a device, make a leaf like the ones OhrTech issues (P-256, `clientAuth`,
the three URIs) with a test root, and connect with
`curl --cert leaf-chain.pem --key leaf.key https://localhost:8443/`, where `leaf-chain.pem` is the
leaf, then the issuing CA, then the root.

## Read the device from the certificate

| Subject alternative name (URI) | |
|---|---|
| `urn:ohrtech:device:dev_3swt6f457299btzpw1bxx4wf0q` | The device: its id in the [Management API](/management-api/) |
| `urn:ohrtech:app:app_7h2m9q4x1c8v3k5n6p0r2s4t6w` | Your app, as in [your apps](/management-api/guides/apps/) |
| `urn:ohrtech:package:com.example.kiosk` | The app's package |

The subject is `CN=dev_…, O=` your organisation's name, so a server that only reads the subject
(nginx's `$ssl_client_s_dn`) still gets the device id. A certificate is issued only for a key the
device attested, for that app, on a verified OhrTech boot: once the chain verifies, these values
are OhrTech's word, not the app's.
