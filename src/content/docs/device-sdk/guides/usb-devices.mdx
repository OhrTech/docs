On Android, an app that opens a USB device has to ask the person using the device first: "Allow
access?". A kiosk without staff can't answer that, and kiosk mode blocks the prompt anyway.
With OhrTech you pre-approve the peripherals each app may use. When one of them is plugged in, the OhrTech Agent
gives the app access to it and makes the app its default handler, so the prompt never appears.
Your app then opens the device with Android's `UsbManager` as usual.

This needs Agent 1061 or later.

## Approve devices for an app

The fleet setting `usb.devices` lists, per app, the USB devices and accessories it may use:

| Entry | Fields |
|---|---|
| A USB device | `vendorId` and `productId`; optionally `serial`, to approve one unit only; optionally `name` |
| A USB accessory (Android Open Accessory) | `manufacturer` and `model`; optionally `name` |

- `vendorId` and `productId` are 0 to 65535, as numbers (`1504`) or as strings in hex (`"0x05e0"`)
  or decimal. They are stored as numbers.
- `name` is your label for it, up to 100 characters. The app sees it, and so does the portal.
- `manufacturer` and `model` are up to 100 characters, `serial` up to 128. They must match what the
  device reports exactly.
- Each app can have up to 50 entries. Duplicates are removed.

Set them with `PUT /v1/fleets/{fleetId}/apps/{appId}/usb-devices` (needs `EditSettings`). The body
replaces this fleet's list for the app, and the hub sends it to the fleet's devices straight away:

```sh
curl -X PUT https://api.ohrtech.net/v1/fleets/flt_2dn47a2xa58j1txv8m28spkmyb/apps/app_7h2m9q4x1c8v3k5n6p0r2s4t6w/usb-devices \
  -H "Authorization: Bearer $OHR_TOKEN" -H "Content-Type: application/json" \
  -d '{
    "devices": [
      { "vendorId": "0x05e0", "productId": "0x1200", "name": "Barcode scanner" },
      { "vendorId": "0x1234", "productId": "0x0001", "serial": "PT-10442", "name": "Lane 1 terminal" },
      { "manufacturer": "Example Payments", "model": "Terminal X", "name": "Payment terminal" }
    ]
  }'
```

The response, like `GET` on the same path (needs `ViewSettings`), shows what applies on the
fleet:

```json
{
  "appId": "app_7h2m9q4x1c8v3k5n6p0r2s4t6w",
  "fleetId": "flt_2dn47a2xa58j1txv8m28spkmyb",
  "devices": [
    { "vendorId": 1504, "productId": 4608, "name": "Barcode scanner" },
    { "vendorId": 4660, "productId": 1, "serial": "PT-10442", "name": "Lane 1 terminal" },
    { "manufacturer": "Example Payments", "model": "Terminal X", "name": "Payment terminal" }
  ],
  "own": [
    { "vendorId": 1504, "productId": 4608, "name": "Barcode scanner" },
    { "vendorId": 4660, "productId": 1, "serial": "PT-10442", "name": "Lane 1 terminal" },
    { "manufacturer": "Example Payments", "model": "Terminal X", "name": "Payment terminal" }
  ],
  "inheritedFrom": null
}
```

An entry that is wrong is refused with a 400, and nothing is stored:

```json
{
  "title": "Bad USB devices",
  "status": 400,
  "detail": "app_7h2m9q4x1c8v3k5n6p0r2s4t6w: a USB device has a vendorId and a productId (0-65535, or hex such as 0x05e0)"
}
```

### Fleets and their parents

The lists merge per app across fleets. For each app, the nearest fleet that has a list for it
wins: a child fleet's list replaces its parent's for that app and leaves the parent's lists for
other apps alone. `own` is this fleet's own list, or `null` when it inherits one, and
`inheritedFrom` names the fleet it comes from.

- An empty list (`"devices": []`) takes away what a parent fleet approves for the app.
- `DELETE /v1/fleets/{fleetId}/apps/{appId}/usb-devices` removes this fleet's list, so the parent
  fleet's applies again.

### In the portal

Open the fleet, go to its **Applications** tab and choose **Change** next to the app. Under **USB
devices**, **Add a device** takes a name, the vendor and product ids (such as `0x05e0`) and an
optional serial number; **Add an accessory** takes a name, a manufacturer and a model. **Save USB
devices** stores them and sends them to the fleet's devices. **Stop setting them here** does what
`DELETE` does.

## Find a device's ids

`GET /v1/devices/{deviceId}/usb-devices` (needs `ViewDevices`) lists every USB device and accessory
attached to a device as of its last report, approved or not, with the apps each is approved for:

```json
{
  "deviceId": "dev_3swt6f457299btzpw1bxx4wf0q",
  "reportedAt": "2026-11-08T14:02:11Z",
  "attached": [
    {
      "deviceName": "/dev/bus/usb/001/004",
      "vendorId": 1504,
      "productId": 4608,
      "manufacturer": "Example Scanners",
      "product": "Handheld scanner",
      "serial": "S24051880",
      "approvedFor": ["com.example.pos"]
    },
    {
      "accessory": true,
      "manufacturer": "Example Payments",
      "model": "Terminal X",
      "version": "2.1",
      "serial": "T7731",
      "approvedFor": []
    }
  ]
}
```

Plug the peripheral into one device, read its ids here, and approve them for the fleet. The device
reports again each time something is attached or detached. In the portal, the device's **App
activity** tab shows the same list.

## On the device

When an approved device or accessory is attached, the Agent grants every app it is approved for
access to it, and makes the first of those apps (in the setting's order) its default handler. It
does the same for what is already attached when the Agent starts or the approvals change.

Each attach and detach is also recorded in the device's events (`source` `agent`, `area` `usb`,
`action` `attached` or `detached`), with the apps the peripheral is approved for. Read them with
`GET /v1/devices/{deviceId}/events`.

### Open it in your app

Open the device with Android's `UsbManager`, as you would without OhrTech. `hasPermission` is
already true, so there is no need to call `requestPermission`:

```kotlin
import android.hardware.usb.UsbDeviceConnection
import android.hardware.usb.UsbManager

val usbManager = context.getSystemService(UsbManager::class.java)
val connections = mutableMapOf<String, UsbDeviceConnection>()

// The approved devices attached now (a binder call: off the main thread):
for (approved in withContext(Dispatchers.IO) { OhrUsb.devices() }) {
    val name = approved.deviceName ?: continue                      // null for an accessory
    val device = usbManager.deviceList[name] ?: continue
    usbManager.openDevice(device)?.let { connections[name] = it }   // no "Allow access?"
}

// Approved devices as they come and go:
OhrUsb.changes.collect { change ->
    val name = change.device.deviceName ?: return@collect
    if (change.attached) usbManager.deviceList[name]?.let { d -> usbManager.openDevice(d)?.let { connections[name] = it } }
    else connections.remove(name)?.close()
}
```

```java
import android.hardware.usb.UsbDevice;
import android.hardware.usb.UsbDeviceConnection;
import android.hardware.usb.UsbManager;

// Off the main thread.
UsbManager usbManager = context.getSystemService(UsbManager.class);
Map<String, UsbDeviceConnection> connections = new ConcurrentHashMap<>();

for (OhrUsb.Device approved : OhrUsb.devices()) {
    if (approved.getAccessory()) continue;
    UsbDevice device = usbManager.getDeviceList().get(approved.getDeviceName());
    if (device == null) continue;
    UsbDeviceConnection connection = usbManager.openDevice(device);   // no "Allow access?"
    if (connection != null) connections.put(device.getDeviceName(), connection);
}

// Approved devices as they come and go; close it to stop:
Closeable watch = OhrUsb.listen(executor, change -> {
    String name = change.getDevice().getDeviceName();
    if (name == null) return;
    if (change.getAttached()) {
        UsbDevice device = usbManager.getDeviceList().get(name);
        UsbDeviceConnection connection = device == null ? null : usbManager.openDevice(device);
        if (connection != null) connections.put(name, connection);
    } else {
        UsbDeviceConnection connection = connections.remove(name);
        if (connection != null) connection.close();
    }
});
```

```dart
import 'package:flutter/services.dart';
```

`ohrtech_device` lists the approved devices and tells you as they come and go; it doesn't open
them. Opening one is Android's `UsbManager`, which Dart can't call: use a USB plugin that opens a
device by its Android device name, or a platform channel to Kotlin code of your app's own, as here.
If the plugin asks for permission first, Android answers at once, without a prompt, since the app
already has it.

For an accessory, find it in `UsbManager`'s accessory list by `manufacturer` and `model`, and open
it with `openAccessory`.

`OhrUsb` needs no fleet grant. It shows the app only the attached peripherals approved for it:

| | Kotlin, Java | Dart | TypeScript | C# |
|---|---|---|---|---|
| The approved devices and accessories attached now | `devices()` | `devices()` | `devices()` | `GetDevicesAsync()` |
| A change each time one is attached (`attached` true) or detached, with its `device` | `changes` (a `Flow<Change>`) / `listen(executor, listener)` | `changes` (a broadcast `Stream<OhrUsbChange>`) | `addChangeListener(listener, onError?)` | the `Changed` event (`Attached`, `Device`) |

Changes go on after the Agent restarts, but one that happened while it was away isn't reported:
call `devices()` again when the connection is back (see [access](/device-sdk/access/)).

A device is an `OhrUsb.Device` in Kotlin and Java, and an `OhrUsbDevice` in Dart, TypeScript and
C# (with the same fields, capitalised, in C#):

| Field | |
|---|---|
| `accessory` | `false` for a USB device, `true` for an accessory |
| `deviceName` | A device's name in `UsbManager`'s device list, such as `/dev/bus/usb/001/004`; null for an accessory |
| `vendorId`, `productId` | A device's ids; `-1` for an accessory |
| `manufacturer`, `product`, `serial` | What the peripheral reports |
| `model`, `version` | An accessory's model and version |
| `name` | Your label for it from the approval, if it has one |
| `hasPermission` | Whether the app may open it now |

On an Agent older than 1061, `devices()` and the changes throw `OhrException.Unsupported`
(`OhrUnsupported` in Dart and TypeScript, `OhrUnsupportedException` in C#) with `needsAgent = 1061`.
In Dart the error arrives on the stream, in TypeScript on `onError`, and in C# on
`OhrDeviceSdk.EventFailed`. See [access](/device-sdk/access/) for the errors and for flows,
streams, listeners and events.
