import { Tabs, TabItem } from '@astrojs/starlight/components';

Four areas of the Device SDK:

| Area | Reads | Changes |
|---|---|---|
| [`device`](#device) (`OhrDevice`) | Always | (nothing to change) |
| [`updates`](#your-apps-updates) (`OhrUpdates`) | Always | Always: it only touches your app |
| [`power`](#power) (`OhrPower`) | Always | The fleet's `power` grant |
| [`settings`](#settings) (`OhrSettings`) | Always | The fleet's `settings` grant |

All four need OhrTech Agent 1059 or later. In Kotlin and Java each call is a blocking call into the
OhrTech Agent: make it off the main thread. `OhrDevice.infoAsync()` does that itself; wrap the others
in `withContext(Dispatchers.IO)`, or call them from a thread of your own in Java. In Dart, TypeScript
and C# the calls are asynchronous already; C# names them `…Async` (`GetInfoAsync()`,
`GetBatteryAsync()`, ...). See [access](/device-sdk/access/) for grants and errors.

## Device

`OhrDevice.info()` says which device your app runs on, as the hub and the
[Management API](/management-api/) name it.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val info = OhrDevice.infoAsync()
show("${info.deviceId} in ${info.fleet?.name}, Agent ${info.agentVersion}, online: ${info.online}")
```

</TabItem>
<TabItem label="Java">

```java
OhrDevice.Info info = OhrDevice.info();   // off the main thread
String fleet = info.getFleet() != null ? info.getFleet().getName() : null;
```

</TabItem>
<TabItem label="Dart">

```dart
final info = await OhrDevice.info();
show('${info.deviceId} in ${info.fleet?.name}, Agent ${info.agentVersion}, online: ${info.online}');
```

</TabItem>
<TabItem label="TypeScript">

```ts
const info = await OhrDevice.info();
const text = `${info.deviceId} in ${info.fleet?.name}, Agent ${info.agentVersion}, online: ${info.online}`;
```

</TabItem>
<TabItem label="C#">

```csharp
var info = await OhrDevice.GetInfoAsync();
label.Text = $"{info.DeviceId} in {info.Fleet?.Name}, Agent {info.AgentVersion}, online: {info.Online}";
```

</TabItem>
</Tabs>

| Field | |
|---|---|
| `deviceId` | The device's id, such as `dev_3swt6f457299btzpw1bxx4wf0q`. `null` until the hub has sent the device its first policy |
| `serial` | The hardware serial number, or `null` |
| `fleet` | `id` (`flt_…`) and `name` of the device's fleet, or `null` |
| `org` | `id` (`org_…`) and `name` of your organisation, or `null` |
| `osRelease` | The Android release, such as `17` |
| `osBuild` | The OhrTech OS build |
| `securityPatch` | The security patch level, such as `2026-11-05` |
| `osIncremental` | The build's incremental version |
| `agentVersion` | The OhrTech Agent's version code |
| `online` | The Agent is connected to the hub now |

In C# the fields are properties (`DeviceId`, `Fleet.Name`, ...).

`deviceId` is the id to send to your server: it is the one the Management API uses in
`/v1/devices/{deviceId}`.

## Your app's updates

When you set one of your app's versions to `available` (see
[apps](/management-api/guides/apps/)), devices download it ahead, over Wi-Fi or Ethernet, and
keep it. Nothing installs it until your app says so: at a quiet moment, after a sale, at the end
of a shift.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
withContext(Dispatchers.IO) {
    val update = OhrUpdates.available()
    if (update != null) OhrUpdates.install(whenIdle = true)
}
```

</TabItem>
<TabItem label="Java">

```java
OhrUpdates.Update update = OhrUpdates.available();   // off the main thread
if (update != null) OhrUpdates.install(true);        // true: when the screen is next off
```

</TabItem>
<TabItem label="Dart">

```dart
final update = await OhrUpdates.available();
if (update != null) await OhrUpdates.install(whenIdle: true);
```

</TabItem>
<TabItem label="TypeScript">

```ts
const update = await OhrUpdates.available();
if (update !== null) await OhrUpdates.install({ whenIdle: true });
```

</TabItem>
<TabItem label="C#">

```csharp
var update = await OhrUpdates.GetAvailableAsync();
if (update is not null) await OhrUpdates.InstallAsync(whenIdle: true);
```

</TabItem>
</Tabs>

`available()` (`GetAvailableAsync()` in C#) returns the offered version, or `null` when none is
offered or your app already runs it or a newer one.

| `Update` field | |
|---|---|
| `versionCode` | The version code |
| `versionName` | The version name, or `null` |
| `notes` | The release notes uploaded with the version, or `null` |
| `downloaded` | `true`: the device has it |

`install(whenIdle)` installs it now (`false`, the default) or the next time the screen turns off
(`true`). In TypeScript it takes `{ whenIdle }`. The call returns at once; the install follows.
Installing replaces your app, so its process stops. If it was on screen, the device starts it again
afterwards; in [kiosk mode](/device-sdk/guides/kiosk/) the watchdog pins it again. The device
reports the outcome to the hub. `install` throws `Unsupported` when nothing is offered.

The offer, each time it changes, comes from `OhrUpdates.changes` (a Kotlin `Flow`, a Dart stream),
`listen(executor, listener)` in Java, `addChangeListener(listener)` in TypeScript, and the `Changed`
event or `Changes(ct)` in C#. When the offer is withdrawn, they give an update with `versionCode` 0:
`OhrUpdates.NONE` in Kotlin and Java, `none` in Dart, `IsNone` in C#. When the Agent restarts, they
give the offer as it is then.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import android.view.View

OhrUpdates.changes.collect { update ->
    updateBanner.visibility = if (update != OhrUpdates.NONE) View.VISIBLE else View.GONE
}
```

</TabItem>
<TabItem label="Java">

```java
import android.view.View;

Closeable watch = OhrUpdates.listen(activity.getMainExecutor(), update ->
    updateBanner.setVisibility(update.equals(OhrUpdates.NONE) ? View.GONE : View.VISIBLE));
```

</TabItem>
<TabItem label="Dart">

```dart
final sub = OhrUpdates.changes.listen((update) => show(update.none ? null : update.versionName));
```

</TabItem>
<TabItem label="TypeScript">

```ts
let offered = false;
const sub = OhrUpdates.addChangeListener((update) => {
  offered = update.versionCode !== 0;
});
```

</TabItem>
<TabItem label="C#">

```csharp
OhrUpdates.Changed += (_, e) => label.Visibility = e.Update.IsNone ? Android.Views.ViewStates.Gone : Android.Views.ViewStates.Visible;
```

</TabItem>
</Tabs>

## Power

Reading the battery and the reboot schedule is always allowed. Everything else needs the `power`
grant.

### Battery

`OhrPower.battery()` (`GetBatteryAsync()` in C#) returns:

| Field | |
|---|---|
| `level` | 0 to 100, or `null` when unknown |
| `charging` | Charging, or full on the charger |
| `plugged` | `ac`, `usb`, `wireless`, `dock`, or `null` when unplugged |
| `health` | `good`, `overheat`, `dead`, `overVoltage`, `cold` or `unknown` |
| `temperatureC` | The battery's temperature, in °C |
| `screenOn` | The screen is on |

It comes again each time it changes, and when the screen turns on or off, from
`OhrPower.batteryChanges` (a Kotlin `Flow`, a Dart stream), `listenBattery(executor, listener)` in
Java, `addBatteryListener(listener)` in TypeScript, and the `BatteryChanged` event or
`BatteryChanges(ct)` in C#.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
OhrPower.batteryChanges.collect { b -> show("${b.level} %, charging: ${b.charging}") }
```

</TabItem>
<TabItem label="Java">

```java
Closeable watch = OhrPower.listenBattery(activity.getMainExecutor(), b ->
    show(b.getLevel() + " %, charging: " + b.getCharging()));
```

</TabItem>
<TabItem label="Dart">

```dart
final sub = OhrPower.batteryChanges.listen((b) => show('${b.level} %, charging: ${b.charging}'));
```

</TabItem>
<TabItem label="TypeScript">

```ts
let text = '';
const sub = OhrPower.addBatteryListener((b) => {
  text = `${b.level} %, charging: ${b.charging}`;
});
```

</TabItem>
<TabItem label="C#">

```csharp
await foreach (var b in OhrPower.BatteryChanges(cancellationToken))
    label.Text = $"{b.Level} %, charging: {b.Charging}";
```

</TabItem>
</Tabs>

### Reboot

`reboot(reason)` reboots the device about 3 seconds later. The hub records `reason`; an empty one
is recorded as `app`.

`scheduleReboot(schedule)` reboots the device on a schedule, in the device's own time zone:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
withContext(Dispatchers.IO) {
    // 03:30 every night except Sunday
    OhrPower.scheduleReboot(OhrPower.Schedule("03:30", setOf(1, 2, 3, 4, 5, 6), "nightly"))
}
```

</TabItem>
<TabItem label="Java">

```java
// 03:30 every night except Sunday
OhrPower.scheduleReboot(new OhrPower.Schedule("03:30", Set.of(1, 2, 3, 4, 5, 6), "nightly"));
```

</TabItem>
<TabItem label="Dart">

```dart
// 03:30 every night except Sunday
await OhrPower.scheduleReboot(const OhrRebootSchedule('03:30', {1, 2, 3, 4, 5, 6}, 'nightly'));
```

</TabItem>
<TabItem label="TypeScript">

```ts
// 03:30 every night except Sunday
await OhrPower.scheduleReboot({ time: '03:30', days: [1, 2, 3, 4, 5, 6], reason: 'nightly' });
```

</TabItem>
<TabItem label="C#">

```csharp
// 03:30 every night except Sunday
await OhrPower.ScheduleRebootAsync(new OhrRebootSchedule("03:30", new HashSet<int> { 1, 2, 3, 4, 5, 6 }, "nightly"));
```

</TabItem>
</Tabs>

| Schedule field | |
|---|---|
| `time` | `HH:mm`, 24-hour |
| `days` | 1 to 7, Monday = 1; at least one day |
| `reason` | What the hub records for each reboot |

The schedule is `OhrPower.Schedule` in Kotlin and Java, `OhrRebootSchedule` in Dart, TypeScript and
C#. A device has one schedule: the last app to set it wins. It is kept across reboots.
`rebootSchedule()` (`GetRebootScheduleAsync()` in C#) returns it, or `null`; `scheduleReboot(null)`
removes it. A time or day that isn't valid throws `InvalidConfig` with `field` `schedule`.

### Screen timeout and brightness

| Call | |
|---|---|
| `setScreenTimeout(seconds)` | Any whole number of seconds, 1 to 2147483 (Android's limit); `InvalidConfig("seconds")` otherwise. Dart takes a `Duration`, C# a `TimeSpan`, in whole seconds |
| `setBrightness(percent)` | 0 to 100; `InvalidConfig("percent")` otherwise. Turns adaptive brightness off |

They change the same settings as the fleet's **Screen timeout** (`display.timeout`) and
**Brightness** (`display.brightness`). When the fleet locks one, the call throws `FleetLocked` with
that key. Otherwise your app's value holds until the fleet changes the setting, as with
[`OhrSettings.set`](#change-a-setting).

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
withContext(Dispatchers.IO) {
    OhrPower.setScreenTimeout(120)
    OhrPower.setBrightness(80)
}
```

</TabItem>
<TabItem label="Java">

```java
OhrPower.setScreenTimeout(120);   // off the main thread
OhrPower.setBrightness(80);
```

</TabItem>
<TabItem label="Dart">

```dart
await OhrPower.setScreenTimeout(const Duration(minutes: 2));
await OhrPower.setBrightness(80);
```

</TabItem>
<TabItem label="TypeScript">

```ts
await OhrPower.setScreenTimeout(120);
await OhrPower.setBrightness(80);
```

</TabItem>
<TabItem label="C#">

```csharp
await OhrPower.SetScreenTimeoutAsync(TimeSpan.FromMinutes(2));
await OhrPower.SetBrightnessAsync(80);
```

</TabItem>
</Tabs>

## Settings

The `settings` area reads and changes the device's settings by the keys of the OhrTech settings
catalogue: the same settings as the portal's Settings tab and the Management API's
[settings](/management-api/guides/settings/). `GET /v1/settings/catalog` describes each key, its
values and its options.

### Read a setting

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
withContext(Dispatchers.IO) {
    val keys = OhrSettings.keys()                     // what apps may use on this device
    val dark = OhrSettings.get("display.dark_theme")  // value true or false, mode "set"
    if (!dark.locked) OhrSettings.set("display.dark_theme", true)
}
```

</TabItem>
<TabItem label="Java">

```java
List<String> keys = OhrSettings.keys();            // off the main thread
OhrSettings.Setting dark = OhrSettings.get("display.dark_theme");
if (!dark.getLocked()) OhrSettings.set("display.dark_theme", true);
```

</TabItem>
<TabItem label="Dart">

```dart
final keys = await OhrSettings.keys();                  // what apps may use on this device
final dark = await OhrSettings.get('display.dark_theme');
if (!dark.locked) await OhrSettings.set('display.dark_theme', true);
```

</TabItem>
<TabItem label="TypeScript">

```ts
const keys = await OhrSettings.keys();                  // what apps may use on this device
const dark = await OhrSettings.get('display.dark_theme');
if (dark.mode !== 'locked') await OhrSettings.set('display.dark_theme', true);
```

</TabItem>
<TabItem label="C#">

```csharp
var keys = await OhrSettings.GetKeysAsync();            // what apps may use on this device
var dark = await OhrSettings.GetAsync("display.dark_theme");
if (!dark.Locked) await OhrSettings.SetAsync("display.dark_theme", true);
```

</TabItem>
</Tabs>

`keys()` (`GetKeysAsync()` in C#) lists the keys apps may read and change on this device.
`get(key)` (`GetAsync(key)`) returns a setting:

| Field | |
|---|---|
| `key` | The key |
| `value` | The value on the device now: a boolean, a number, a string, an array, an object or `null` |
| `mode` | `unmanaged` (the fleet leaves it alone), `set` (the fleet set it; it may be changed) or `locked` (the fleet locks it) |
| `locked` | `mode` is `locked` (not in TypeScript: compare `mode`) |

The value is a `Boolean`, `Int`, `String`, `JSONArray`, `JSONObject` or `null` in Kotlin and Java,
the decoded JSON (`bool`, `num`, `String`, `List`, `Map` or `null`) in Dart and TypeScript, and a
`JsonNode?` in C#. It has the catalogue's shape for that key. A choice is a string even when it
looks like a number: `display.timeout` is `"300"`, not `300`. `display.brightness` reads `-1` while
adaptive brightness is on. A key that isn't in `keys()` throws `Unsupported`.

### Change a setting

Needs the `settings` grant. `set(key, value)` (`SetAsync(key, value)` in C#) takes a value in the
catalogue's shape: a boolean, a number, a string, an array, an object or `null` (in Kotlin and Java
`JSONArray` and `JSONObject` for the last two, in C# a `JsonNode`).

These are the settings an app can read and change, with the values each takes:

| Kind | Settings | Values |
|---|---|---|
| On or off | `wifi.enabled`, `bluetooth.enabled`, `network.data_roaming`, `telephony.calls_and_texts`, `location.enabled`, `notifications.dnd`, `notifications.cooldown`, `notifications.camera_flash`, `notifications.screen_flash`, `notifications.emergency_alerts`, `battery.show_percentage`, `sound.vibration`, `display.dark_theme`, `display.auto_rotate`, `display.lift_to_wake`, `safety.emergency_sos`, `system.auto_time_zone`, `dev.stay_awake`, `dev.show_taps`, `dev.pointer_location` | `true` or `false` |
| Percent | `sound.media_volume`, `sound.ring_volume`, `sound.alarm_volume`, `display.brightness`, `battery.saver_threshold` | A whole number, 0 to 100 |
| Seconds | `display.timeout` | A whole number of seconds, 1 to 2147483 (Android's limit) |
| Choice | `display.font_size`, `display.size` | `small`, `default`, `large` or `largest` |
| App | `apps.browser`, `apps.sms` | A package name, or `default` |
| Time zone | `system.time_zone` | An IANA zone, such as `Europe/Amsterdam` |
| Lists | `system.languages`; `system.input_methods` | Language tags such as `de-DE`; input method ids such as `com.example.keyboard/.ImeService`, or `default` |

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import org.json.JSONArray

withContext(Dispatchers.IO) {
    OhrSettings.set("display.auto_rotate", true)
    OhrSettings.set("display.timeout", 45)
    OhrSettings.set("system.languages", JSONArray(listOf("de-DE", "en-US")))
}
```

</TabItem>
<TabItem label="Java">

```java

```

</TabItem>

</TabItem>
<TabItem label="TypeScript">

<TabItem label="C#">

```csharp

```

</TabItem>

A value that doesn't fit throws `InvalidConfig` (`field` `value`, and `reason` says what it must be),
before anything changes. The device applies a valid value straight away and reports it to the hub,
where it shows in the device's `reported` settings. A value the device can't apply anyway throws
`Failed`.

Who wins:

- A key the fleet **locks** refuses the change: `FleetLocked(key)`.
- A key the fleet **sets**, or leaves unmanaged, takes your app's value. It holds until the fleet
  changes that setting; then the fleet's new value applies.
- The person at the device can change an unlocked setting too, like any setting.

### What apps can't change

Only the settings above are in `keys()`; `get` and `set` refuse every other key with `Unsupported`,
whatever the grant. The rest are the fleet's control of the device (screen lock, kiosk mode, Wi-Fi
networks, the Device SDK grants, remote control, USB debugging, factory reset, each app's
configuration and certificates, and so on), and a setting the catalogue gains later stays out of
apps' reach until it is added here. Kiosk mode and Wi-Fi networks have their own areas:
[kiosk](/device-sdk/guides/kiosk/), [Wi-Fi](/device-sdk/guides/wifi-and-networks/).

### Follow changes

A setting comes each time its value changes on the device, whoever changed it: the fleet, your
app, another app or the person at the device. It comes from `OhrSettings.changes` (a Kotlin `Flow`,
a Dart stream), `listen(executor, listener)` in Java, `addChangeListener(listener)` in TypeScript,
and the `Changed` event or `Changes(ct)` in C#. They go on when the Agent restarts, but a change
made while it was away isn't sent: read the settings you need again then (see
[following changes](/device-sdk/access/#following-changes)).

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
OhrSettings.changes
    .filter { it.key == "display.dark_theme" }
    .collect { applyTheme(dark = it.value == true) }
```

</TabItem>
<TabItem label="Java">

```java
Closeable watch = OhrSettings.listen(activity.getMainExecutor(), setting -> {
    if (setting.getKey().equals("display.dark_theme")) applyTheme(Boolean.TRUE.equals(setting.getValue()));
});
```

</TabItem>
<TabItem label="Dart">

```dart
final sub = OhrSettings.changes
    .where((s) => s.key == 'display.dark_theme')
    .listen((s) => applyTheme(dark: s.value == true));
```

</TabItem>
<TabItem label="TypeScript">

```ts
let dark = false;
const sub = OhrSettings.addChangeListener((s) => {
  if (s.key === 'display.dark_theme') dark = s.value === true;
});
```

</TabItem>
<TabItem label="C#">

```csharp
OhrSettings.Changed += (_, e) =>
{
    if (e.Setting.Key == "display.dark_theme") label.Text = e.Setting.Value?.GetValue<bool>() == true ? "Dark" : "Light";
};
```

</TabItem>
</Tabs>

## Errors

| Exception | When |
|---|---|
| `NotAllowed("power")`, `NotAllowed("settings")` | A change without the fleet's grant |
| `FleetLocked(key)` | The fleet locks the setting |
| `InvalidConfig(field, reason)` | A setting value, screen timeout, brightness or reboot schedule that isn't valid |
| `Unsupported` | `install` with nothing offered; `get` or `set` of a key apps can't use |
| `Failed(reason)` | The device couldn't apply it |

These are the Kotlin and Java names (`OhrException.NotAllowed`, ...). Dart and TypeScript name them
`OhrNotAllowed`, `OhrFleetLocked`, ...; C# `OhrNotAllowedException`, `OhrFleetLockedException`, ...
See [errors](/device-sdk/access/#errors).
