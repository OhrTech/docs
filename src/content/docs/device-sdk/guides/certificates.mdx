When your servers ask for a client certificate (mutual TLS), your app can present one without a
key in the APK or a file to copy onto each device:

- **Device-made.** Your app makes a key in its Android Keystore, in the TEE. OhrTech certifies it
  with your organisation's issuing CA, only after checking the key's attestation: this device, this
  app, a verified OhrTech boot. The certificate names the device, the app and the package. The key
  never leaves the TEE.
- **Imported.** PKCS#12 bundles from your existing PKI, which the fleet gives your app.
- **Trusted CAs.** Private CAs your app trusts for your servers, besides the system's.

The fleet decides which of these the app gets, per app. Setting it up (the issuing CA, your client
root, the fleet) is on [client certificates on your server](/device-sdk/server/client-certificates/).
Certificates need OhrTech Agent 1061 or later; on an older Agent every call here throws
`OhrException.Unsupported` with `needsAgent = 1061`. They need no grant from the fleet.

## Get a certificate and use it

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
withContext(Dispatchers.IO) {
    val certs = sdk.certificates
    if (certs.list().none { it.alias == "orders" && !it.imported }) certs.request("orders")
    else certs.renewIfDue("orders")

    val c = URL("https://orders.example.com/").openConnection() as HttpsURLConnection
    c.sslSocketFactory = certs.sslContext("orders").socketFactory
    c.inputStream.use { /* ... */ }
}
```

</TabItem>
<TabItem label="Java">

```java
// Off the main thread.
OhrCertificates certs = sdk.getCertificates();
boolean have = false;
for (OhrCertificates.Certificate c : certs.list())
    if (c.getAlias().equals("orders") && !c.getImported()) have = true;
if (!have) certs.request("orders");
else certs.renewIfDue("orders");

HttpsURLConnection c = (HttpsURLConnection) new URL("https://orders.example.com/").openConnection();
c.setSSLSocketFactory(certs.sslContext("orders").getSocketFactory());
```

</TabItem>
</Tabs>

Every call here is a binder call, and `request` waits for OhrTech: make them off the main thread.

## Device-made certificates

`request(alias, timeoutMs = 60_000)` makes a new EC P-256 key in the app's Keystore, has it attested,
and asks OhrTech to certify it. It takes a few seconds and needs the device online. The alias is
your name for it: 1 to 64 of `A-Z a-z 0-9 . _ -`. A new request under the same alias replaces the
key and certificate before it.

`canRequest()` says whether the fleet gives your app an issuing CA, so that `request` can work.

OhrTech issues the certificate only when the attestation holds: the key was made in the TEE of this
device, for your app's package, on a verified, locked OhrTech boot. What you get:

| | |
|---|---|
| Subject | `CN=dev_…` (the device id), `O=` your organisation's name |
| Subject alternative names | `urn:ohrtech:device:dev_…`, `urn:ohrtech:app:app_…`, `urn:ohrtech:package:` your package |
| Key | EC P-256, in the TEE. It can sign, so it works for TLS; it can't be exported. |
| Usage | Digital signature, client authentication |
| Valid | From an hour before it was issued, for the issuing CA's `leafDays` (90 by default), and never past the issuing CA's own expiry |
| Issuer | Your organisation's issuing CA |

### Renewal

`renewIfDue(alias)` asks for a new key and certificate when less than a third of the certificate's
lifetime is left, and returns null when it isn't due (or there is no device-made certificate under
that alias). Call it when your app starts and once a day. A renewal makes a new key: the old one is
deleted once the new certificate is in.

`keyManager` and `sslContext` take the certificates as they are when you call them. After a
`request` or a renewal, make a new `SSLContext` (and a new OkHttp client).

### Two paths to two roots

A device-made certificate validates two ways:

- through your **organisation's client root**, once you have signed the issuing CA with it, and
- through the **OhrTech Device Identity Root**, which OhrTech signs every issuing CA with.

Both copies of the issuing CA have the same subject and key, so the certificate verifies under
either. `Certificate.paths` holds both, each leaf first, the organisation's first; `chain` is the
first path. TLS sends one chain, and servers built on OpenSSL, such as nginx and Apache httpd, take
the first issuer they find and don't try another: sent both copies, they fail when the
organisation's copy comes first and they trust only the OhrTech root.

So the key manager sends one path, picked by the CA names the server lists in its certificate
request: the path that contains a listed name. When the server lists none, it sends the first path,
the organisation's (or the OhrTech one, before your organisation has uploaded its certificate). When
the server lists names and no path has any of them, it sends no certificate. Servers list the CAs
they trust by default: nginx from `ssl_client_certificate`, Go from `ClientCAs`. See
[server configuration](/device-sdk/server/client-certificates/#configure-your-server).

## Imported certificates

A fleet can give your app client certificates from your own PKI, as PKCS#12 with its password. The
first call to `list()`, `keyManager()` or `sslContext()` installs each into your app's Keystore,
under the alias the fleet gave it, and removes the ones the fleet took away. They appear in `list()`
with `imported = true`. EC and RSA keys work. The key came from your PKI, so copies of it can exist
outside the device; it is in the Keystore from then on.

## Trusted CAs

`trustManager()` trusts the system's CAs and the private CAs the fleet gives your app. A server
certificate is checked against the system's CAs first, then the fleet's. `sslContext()` uses it.
Without private CAs from the fleet, it is the system's trust manager.

## With OkHttp

OkHttp needs the trust manager as well as the socket factory:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val km = sdk.certificates.keyManager("orders")
val tm = sdk.certificates.trustManager()
val tls = SSLContext.getInstance("TLS").apply { init(arrayOf(km), arrayOf(tm), null) }
val client = OkHttpClient.Builder().sslSocketFactory(tls.socketFactory, tm).build()
```

</TabItem>
<TabItem label="Java">

```java
X509ExtendedKeyManager km = sdk.getCertificates().keyManager("orders");
X509TrustManager tm = sdk.getCertificates().trustManager();
SSLContext tls = SSLContext.getInstance("TLS");
tls.init(new KeyManager[] {km}, new TrustManager[] {tm}, null);
OkHttpClient client = new OkHttpClient.Builder().sslSocketFactory(tls.getSocketFactory(), tm).build();
```

</TabItem>
</Tabs>

## The API

| | |
|---|---|
| `canRequest()` | Whether the fleet gives the app an issuing CA |
| `request(alias, timeoutMs)` | A new key and certificate under `alias` |
| `renewIfDue(alias)` | A new key and certificate when a third of the lifetime is left, else null |
| `list()` | The app's certificates, device-made and imported, as `Certificate`: `alias`, `paths`, `chain`, `certificate` (the leaf), `imported` |
| `keyManager(alias)` | An `X509ExtendedKeyManager` presenting `alias`'s certificate, or, with null, any of the app's |
| `trustManager()` | An `X509TrustManager`: the system's CAs and the fleet's private CAs |
| `sslContext(alias)` | A TLS `SSLContext` with both |
| `changes` / `listen(executor, listener)` | The fleet changed the app's certificates: its issuing CA, trusted CAs or imported bundles. Kotlin `Flow<Unit>`; Java listener, close the returned `Closeable` to stop. |

When `changes` fires, build a new `SSLContext`, and call `request` if `canRequest()` became true.

## Errors

`request` throws `OhrException.Refused` when OhrTech declines to certify the key; `reason` says why:

| `reason` | |
|---|---|
| `the fleet gives this app no issuing CA` | Set one for the app on the fleet. |
| `the issuing CA is not this organisation's, or revoked` | The fleet names an issuing CA that was revoked, or another organisation's. |
| `attestation: …` | The key's attestation did not verify, for example `the key is not in the TEE`. |
| `the key was attested by another device` | The attestation names a different device than the one asking. |
| `verified boot is …, not verified`, `the bootloader is not locked`, `the device did not boot with OhrTech's key` | The device is not running OhrTech's verified OS. Several reasons are joined with `; `. |
| `OS patch level … is older than …` | The device needs an OS update first. |
| `the key is not …'s` | The key was attested for another package. |
| `unknown app`, `malformed request` | The request could not be matched to your app, or could not be read. |

| Other errors | |
|---|---|
| `OhrException.Failed` | The device can't reach OhrTech now (`the hub isn't reachable now`), or OhrTech did not answer within `timeoutMs`. Try again later. |
| `OhrException.Unsupported` | The Agent is older than 1061. |
| `IllegalArgumentException` | The alias is not 1 to 64 of `A-Z a-z 0-9 . _ -`. |
