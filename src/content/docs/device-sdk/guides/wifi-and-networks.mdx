Two areas cover the device's connectivity:

- `wifi`: Wi-Fi on or off, the networks in range, saved networks, and saving, joining and
  forgetting networks of every type the device supports, enterprise and Passpoint included.
- `network`: the active network, mobile data, airplane mode and data roaming.

Any app the hub installed can read both. Changing anything needs the fleet's grant: `wifi` for the
Wi-Fi area and the embedded Wi-Fi screen, `network` for mobile data, airplane mode and roaming. See
[access](/device-sdk/access/) for how grants are set.

Both areas, and the embedded screen, need OhrTech Agent 1059 or later. Every call on this page
except the `Flow` properties is a blocking call into the OhrTech Agent: make it off the main thread.

## Join a network

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val sdk = OhrDeviceSdk.connect(context)
withContext(Dispatchers.IO) {
    if (sdk.session.mayUse("wifi")) {
        val identity = sdk.wifi.connect(WifiConfig.psk("Store-Backoffice", "correct horse battery"))
        // identity is "ssid:Store-Backoffice"
    }
}
```

</TabItem>
<TabItem label="Java">

```java
OhrDeviceSdk sdk = OhrDeviceSdk.connectBlocking(context);   // off the main thread
if (sdk.getSession().mayUse("wifi")) {
    String identity = sdk.getWifi().connect(WifiConfig.psk("Store-Backoffice", "correct horse battery"));
}
```

</TabItem>
</Tabs>

`connect(config)` saves the network, then joins it. `save(config)` only saves it. Both return the
network's **identity**: `ssid:<name>`, or `passpoint:<fqdn>` for a Passpoint provider. Saving
replaces any saved network with the same SSID, whatever its security, or the same Passpoint
provider.

## Read the Wi-Fi state

| Call | Returns |
|---|---|
| `state()` | `State`: `enabled`, `state` (`on`, `off`, `turningOn`, `turningOff`), `connected` (the current network as JSON, or `null`) |
| `networks()` | The networks in range, as `Network` |
| `scan()` | Starts a scan; the results arrive in `networks()` and `networkChanges` |
| `saved()` | The saved networks, as JSON objects |

Each `Network` has:

| Field | |
|---|---|
| `key` | Pass it to `connect(key)` to join this network |
| `title` | The name to show |
| `ssid` | The SSID, or `null` (Passpoint) |
| `security` | The security types it offers, such as `["psk", "sae"]` |
| `level` | Signal level, as Android's Settings shows it |
| `saved`, `connected` | Saved on the device; the device is connected to it now |
| `fleet` | One of the fleet's networks (read-only to apps) |
| `json` | The full JSON, which also has `internet`, `metered`, `summary` and `connected` as `connected`, `connecting` or `disconnected` |

The first `networks()` call can take up to about 3 seconds while the list starts. The list then
keeps running for a minute, or for as long as you follow `networkChanges`, so later calls answer
at once.

`saved()` lists each network as `{"ssid", "security", "fleet"}`, or a Passpoint provider as
`{"security": "passpoint", "passpoint": {"fqdn", "friendlyName"}, "fleet"}`. It never contains a
password.

## Change Wi-Fi

Needs the `wifi` grant.

| Call | |
|---|---|
| `save(config)` | Saves a network; returns its identity |
| `connect(config)` | Saves, then joins; returns the identity |
| `connect(keyOrIdentity)` | Joins a network in range by its `key`, or a saved network by its `ssid:` identity |
| `disconnect()` | Leaves the current network |
| `forget(identity)` | Removes a saved network (`ssid:…` or `passpoint:…`) |
| `setEnabled(on)` | Turns Wi-Fi on or off. `FleetLocked("wifi.enabled")` when the fleet locks it |
| `connectQr(text)` | Saves and joins the network in a Wi-Fi QR code your app scanned |

`connect(key)` with a key that is not in range, or an identity that is not saved, throws
`InvalidConfig` with `field` `network`. To join a network that isn't saved and needs a password or
more, pass a config instead of its key. Passpoint providers are joined automatically when one of
their networks is in range.

### QR codes

`connectQr` takes the text of a standard Wi-Fi QR code, the kind Android's "Share Wi-Fi" shows:

```text
WIFI:T:WPA;S:Store-Backoffice;P:correct horse battery;H:false;;
```

`T` is `WPA` or `WPA2` (saved as `psk`), `SAE`, `WEP`, `WPA2-EAP` or `WPA3-EAP` (saved as `eap`),
or `nopass`. For enterprise codes it reads `E` (method), `PH2` (phase 2), `I` (identity), `A`
(anonymous identity) and `P` (password); a PEAP or TTLS network from a QR code trusts the
server's certificate on first use, since the code carries no CA. A text that isn't a Wi-Fi code
throws `InvalidConfig` with `field` `qr`. Easy Connect codes (`DPP:…`) throw `Unsupported`.

## Network configs

A config is a JSON object in the OhrTech Wi-Fi model: the same model as the fleet setting
**Saved Wi-Fi networks** (`wifi.networks`) in the portal and the
[Management API](/management-api/guides/settings/). `WifiConfig` builds the common ones:

| Builder | `security` |
|---|---|
| `WifiConfig.open(ssid, hidden)` | `open` |
| `WifiConfig.owe(ssid, hidden)` | `owe` (Enhanced Open) |
| `WifiConfig.psk(ssid, password, hidden)` | `psk` (WPA/WPA2-Personal) |
| `WifiConfig.sae(ssid, password, hidden)` | `sae` (WPA3-Personal) |

`hidden` is optional and `false` by default. For everything else, build the JSON. The device checks
a config strictly, with the same rules as the hub: an unknown field, a value of the wrong type or a
missing value throws `InvalidConfig`, whose `field` is the JSON path (`password`,
`eap.domain`, `passpoint.credential.imsi`) and whose `reason` says what to fix.

### Every network

| Field | Values | Default |
|---|---|---|
| `ssid` | The network name, at most 32 bytes in UTF-8. Not for Passpoint | |
| `security` | See below | `psk` |
| `password` | For `psk`, `sae`, `wep` and `wapi-psk` | |
| `hidden` | `true` for a network that doesn't broadcast its name | `false` |
| `bssid` | Join only this access point, `aa:bb:cc:dd:ee:ff` | |
| `autoJoin` | Join it automatically | `true` |
| `mac` | `persistent` (a random MAC per network), `non-persistent` (a new one now and then), `device` (the hardware MAC) | `persistent` |
| `metered` | `auto`, `metered`, `unmetered` | `auto` |
| `proxy` | `{"type": "none"}`, `{"type": "manual", "host", "port", "exclusions": [...]}` or `{"type": "pac", "pacUrl"}` | none |
| `ip` | `{"type": "dhcp"}`, or `{"type": "static", "address": "192.168.1.20/24", "gateway", "dns": [up to 2]}` | DHCP |
| `eap` | The enterprise settings, for `eap`, `eap-wpa3` and `eap-suite-b` | |
| `passpoint` | The provider, for `passpoint` | |

### Security types

| `security` | | Password |
|---|---|---|
| `open` | No security | none |
| `owe` | Enhanced Open | none |
| `wep` | WEP | 5, 13 or 16 characters, or 10, 26 or 32 hex digits |
| `psk` | WPA/WPA2-Personal; Android uses WPA3 where the access point offers it | 8 to 63 printable ASCII characters, or 64 hex digits |
| `sae` | WPA3-Personal only | 8 to 128 characters |
| `wapi-psk` | WAPI PSK | 8 to 64 characters |
| `eap` | WPA/WPA2/WPA3-Enterprise | under `eap` |
| `eap-wpa3` | WPA3-Enterprise only | under `eap` |
| `eap-suite-b` | WPA3-Enterprise 192-bit; needs EAP-TLS | under `eap` |
| `passpoint` | A Passpoint (Hotspot 2.0) provider | under `passpoint.credential` |

The device joins WEP networks only where the fleet allows them (the setting **WEP Wi-Fi networks**,
off by default). Otherwise Android refuses the network and the call throws `Failed`.

### Enterprise (EAP)

| Field | Values |
|---|---|
| `method` | `peap` (default), `ttls`, `tls`, `pwd`, `sim`, `aka`, `aka-prime` |
| `phase2` | PEAP: `mschapv2`, `gtc`, `sim`, `aka`, `aka-prime`. TTLS: `pap`, `mschap`, `mschapv2`, `gtc`. Required for these two; leave it out for the others |
| `identity` | Required for PEAP, TTLS, TLS and PWD |
| `anonymousIdentity` | The outer identity, optional |
| `password` | Required for PEAP, TTLS and PWD; not allowed for the others |
| `ca` | How the server's certificate is checked: `system` (Android's trusted CAs; needs `domain`), `certs` (the PEM certificates in `caCertificates`) or `tofu` (trust on first use) |
| `caCertificates` | PEM certificates, with `ca: certs` only |
| `domain` | The server's domain, matched as a suffix, such as `radius.example.com` |
| `ocsp` | `none` (default), `request`, `require`, `require-all`. Not with `tofu` |
| `clientPkcs12` | EAP-TLS: the client certificate and key, as a base64 PKCS#12 |
| `clientPkcs12Password` | The PKCS#12's password, if it has one |
| `minTls` | `1.0`, `1.1`, `1.2` or `1.3`; Android's own minimum when absent |

`ca`, `caCertificates`, `domain`, `ocsp` and `minTls` apply to PEAP, TTLS and TLS only: SIM, AKA,
AKA' and PWD don't check a server certificate. The EAP-TLS client certificate must be an end-entity
certificate with its private key, not a CA certificate.

### Passpoint

A Passpoint provider has no `ssid`, `hidden`, `bssid`, `password`, `eap`, `proxy` or `ip`. The
device joins any network the provider runs.

| Field | |
|---|---|
| `passpoint.fqdn` | The provider's domain. Its identity is `passpoint:<fqdn>`, in lower case |
| `passpoint.friendlyName` | The name to show |
| `passpoint.realm` | The realm |
| `passpoint.roamingConsortiums` | Roaming consortium OIs, 6 or 10 hex digits each, optional |
| `passpoint.caCertificates` | PEM certificates of the provider's authentication server; Android's trusted CAs when absent |
| `passpoint.credential` | One of the three below |

| `credential.type` | Fields |
|---|---|
| `user` (default) | `username`, `password`, `method`: `pap`, `mschap` or `mschapv2` (default) |
| `cert` | `clientPkcs12`, `clientPkcs12Password` |
| `sim` | `imsi` (up to 15 digits, or a prefix ending in `*` such as `310150*`), `simMethod`: `sim` (default), `aka` or `aka-prime` |

```json
{
  "security": "passpoint",
  "passpoint": {
    "fqdn": "hotspot.example.com",
    "friendlyName": "Example Hotspot",
    "realm": "example.com",
    "credential": { "type": "user", "username": "store-0042", "password": "…", "method": "mschapv2" }
  }
}
```

## The fleet's networks

Networks the fleet puts in **Saved Wi-Fi networks** are the fleet's. Your app sees them, marked
`fleet: true`, and can join them, but it can't save over them or forget them: `save`, `connect(config)`
and `forget` with one of their identities throw `FleetLocked` with `key` `wifi.networks`. The
same goes for `setEnabled` when the fleet locks Wi-Fi on or off (`key` `wifi.enabled`).

Change the fleet's networks in the portal or with the
[Management API](/management-api/guides/settings/).

## The embedded Wi-Fi screen

`OhrWifiView` is a complete Wi-Fi screen in the look of Android's Settings, drawn by the OhrTech
Agent inside your own layout: the Wi-Fi switch, the networks in range, joining one, its details,
**Add network** and **Saved networks**. Touch, the keyboard and TalkBack work as in your own views.
It needs the `wifi` grant.

```xml
<net.ohrtech.device.OhrWifiView
    android:id="@+id/wifi"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />
```

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val wifiView = findViewById<OhrWifiView>(R.id.wifi)
wifiView.listener = object : OhrWifiView.Listener {
    override fun onConnected(ssid: String) { showStatus("Joined $ssid") }
    override fun onError(error: Exception) { showStatus("Wi-Fi screen: ${error.message}") }
}
wifiView.attach(sdk)
```

</TabItem>
<TabItem label="Java">

```java
OhrWifiView wifiView = findViewById(R.id.wifi);
wifiView.setListener(new OhrWifiView.Listener() {
    @Override public void onConnected(String ssid) { showStatus("Joined " + ssid); }
    @Override public void onError(Exception error) { showStatus("Wi-Fi screen: " + error.getMessage()); }
});
wifiView.attach(sdk);
```

</TabItem>
</Tabs>

`attach` may be called from the main thread: the view opens the screen once it is laid out and
makes its calls to the Agent on a thread of its own. It closes when the view leaves the window.
With `layout_height="wrap_content"` the view takes the screen's own height. `onError` gets an
`OhrException` when the Agent refuses, such as `NotAllowed` without the `wifi` grant.

### Why it suits a kiosk

The screen opens no activity, dialog or window of its own: its dialogs and lists are drawn inside
the view. Nothing in it leads to Settings or to another app, so an app in
[kiosk mode](/device-sdk/guides/kiosk/) can offer Wi-Fi without leaving kiosk mode. Your app
doesn't have to build its own network forms.

### What it offers

Set `options` before `attach`. Everything is on by default.

| Option | Off hides |
|---|---|
| `wifiSwitch` | The **Use Wi-Fi** switch |
| `addNetwork` | **Add network** |
| `enterprise` | Joining or adding enterprise networks ("Ask your organisation to add this network") |
| `forget` | **Forget** |
| `saved` | **Saved networks** |

The screen follows the fleet: the fleet's networks show "Managed by your organisation" and can't be
forgotten, and when the fleet locks Wi-Fi on or off the switch is greyed out. Adding a network
offers None, Enhanced Open, WEP, WPA/WPA2-Personal, WPA3-Personal, WPA/WPA2/WPA3-Enterprise and
WPA3-Enterprise, with the EAP methods PEAP, TTLS, PWD, SIM, AKA and AKA'. Networks that need a
certificate or a provider profile (EAP-TLS, Passpoint) are for the fleet's settings or your own
`save` call.

### The look

Unset values follow the device's Material You colours, as Settings does. `theme` can change while
the screen is open, when your app switches to dark for example.

| `Theme` field | |
|---|---|
| `dark` | Dark or light; the system's choice when `null` |
| `accent` | Accent colour, ARGB |
| `background` | Background colour, ARGB |
| `text` | Text colour, ARGB |
| `cornerRadiusDp` | Corner radius of dialogs, the switch bar and buttons, 0 to 32 dp (Settings' own when `null`) |

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
wifiView.options = OhrWifiView.Options(addNetwork = false, forget = false)
wifiView.theme = OhrWifiView.Theme(dark = true, accent = 0xFF1E88E5.toInt(), cornerRadiusDp = 12f)
```

</TabItem>
<TabItem label="Java">

</TabItem>

An app can have up to 4 screens open at once; opening another closes its oldest.

## Mobile data, airplane mode and roaming

`network.state()` returns:

| Field | |
|---|---|
| `active` | The network in use, or `null` when there is none |
| `active.transport` | `wifi`, `cellular`, `ethernet`, `vpn` or `other` |
| `active.validated` | Android confirmed it reaches the internet |
| `active.captive` | It is behind a sign-in page (captive portal) |
| `active.metered` | It is metered |
| `active.vpn` | It goes through a VPN |
| `mobileData` | Mobile data is on |
| `airplaneMode` | Airplane mode is on |
| `dataRoaming` | Data roaming is on |
| `ethernetConnected` | An Ethernet network is connected |

With the `network` grant: `setMobileData(on)`, `setAirplaneMode(on)` and `setDataRoaming(on)`.
`setDataRoaming` throws `FleetLocked("network.data_roaming")` when the fleet locks the setting.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
withContext(Dispatchers.IO) {
    val s = sdk.network.state()
    if (s.active == null && !s.mobileData) sdk.network.setMobileData(true)
}
```

</TabItem>
<TabItem label="Java">

```java
OhrNetwork.State s = sdk.getNetwork().state();
if (s.getActive() == null && !s.getMobileData()) sdk.getNetwork().setMobileData(true);
```

</TabItem>
</Tabs>

:::caution
Turning roaming off on a device whose SIM always roams, as many IoT SIMs do, leaves it reachable
only over Wi-Fi.
:::

## Follow changes

| Kotlin `Flow` | Java listener | Gives |
|---|---|---|
| `wifi.stateChanges` | `wifi.listenState(executor, listener)` | `OhrWifi.State` |
| `wifi.networkChanges` | `wifi.listenNetworks(executor, listener)` | `List<Network>` |
| `network.changes` | `network.listen(executor, listener)` | `OhrNetwork.State` |

A change is sent when something differs from the last one sent. Following `networkChanges` keeps the
network list running, which scans now and then; stop when you no longer show it.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        sdk.wifi.networkChanges.collect { networks -> adapter.submitList(networks) }
    }
}
```

</TabItem>
<TabItem label="Java">

```java
Closeable watch = sdk.getWifi().listenNetworks(getMainExecutor(), networks -> adapter.submitList(networks));
// later, in onStop():
watch.close();
```

</TabItem>
</Tabs>

## Errors

| Exception | When |
|---|---|
| `NotAllowed("wifi")`, `NotAllowed("network")` | A change, or the Wi-Fi screen, without the fleet's grant |
| `FleetLocked(key)` | `wifi.networks`, `wifi.enabled` or `network.data_roaming`, as above |
| `InvalidConfig(field, reason)` | A config, identity, key or QR code that isn't valid |
| `Unsupported` | Easy Connect QR codes; a device whose Wi-Fi list can't run |
| `Failed(reason)` | Android refused, such as a WEP network the fleet doesn't allow |
