import { Tabs, TabItem } from '@astrojs/starlight/components';

Managed configuration gives your app settings that you set from the hub instead of building them
into the APK: the server address, the store number, a printer, an API key. You declare the settings
in the app. The hub reads them from the APK you upload, and the OhrTech Portal shows a form for
them. You set the values for a fleet or for a single device, and the app reads them with
`OhrConfig`.

This is Android's standard application restrictions mechanism. The OhrTech Agent sets the values as
the app's application restrictions, so code that already reads them with `RestrictionsManager` works
unchanged.

## Declare the settings

Put the settings in `res/xml/app_restrictions.xml` of the app's Android project. The file is the
same for every framework:

```xml
<?xml version="1.0" encoding="utf-8"?>
<restrictions xmlns:android="http://schemas.android.com/apk/res/android">
    <restriction android:key="server_url" android:restrictionType="string"
        android:title="Server" android:defaultValue="https://pos.example.com" />
    <restriction android:key="store_number" android:restrictionType="integer"
        android:title="Store number" android:defaultValue="0" />
    <restriction android:key="kiosk_on_start" android:restrictionType="bool"
        android:title="Start in kiosk mode" android:defaultValue="false" />
    <restriction android:key="mode" android:restrictionType="choice" android:title="Mode"
        android:entries="@array/mode_labels" android:entryValues="@array/mode_values"
        android:defaultValue="customer" />
    <restriction android:key="features" android:restrictionType="multi-select" android:title="Features"
        android:entries="@array/feature_labels" android:entryValues="@array/feature_values" />
    <restriction android:key="api_key" android:restrictionType="hidden" android:title="API key" />
    <restriction android:key="printer" android:restrictionType="bundle" android:title="Printer">
        <restriction android:key="host" android:restrictionType="string" android:title="Host" />
        <restriction android:key="port" android:restrictionType="integer" android:title="Port"
            android:defaultValue="9100" />
    </restriction>
    <restriction android:key="lanes" android:restrictionType="bundle_array" android:title="Lanes">
        <restriction android:key="lane" android:restrictionType="bundle" android:title="Lane">
            <restriction android:key="name" android:restrictionType="string" android:title="Name" />
        </restriction>
    </restriction>
</restrictions>
```

Then point to the file from the `<application>` element of your manifest:

```xml
<meta-data android:name="android.content.APP_RESTRICTIONS"
    android:resource="@xml/app_restrictions" />
```

Where the two files are in each kind of project:

| Project | `app_restrictions.xml` | The manifest |
|---|---|---|
| Android (Kotlin, Java) | `app/src/main/res/xml/` | `app/src/main/AndroidManifest.xml` |
| Flutter | `android/app/src/main/res/xml/` | `android/app/src/main/AndroidManifest.xml` |
| React Native | `android/app/src/main/res/xml/` | `android/app/src/main/AndroidManifest.xml` |
| .NET MAUI | `Platforms/Android/Resources/xml/` | `Platforms/Android/AndroidManifest.xml` |
| .NET for Android | `Resources/xml/` | `AndroidManifest.xml` |

An Expo app generates its `android` directory with `npx expo prebuild`, which replaces what you
put there. Add the file and the `<meta-data>` element with a config plugin of your own, or keep the
`android` directory in your repository. The Device SDK's config plugin only sets `minSdkVersion`.

| `restrictionType` | The value | Kotlin, Java | Dart, TypeScript | C# |
|---|---|---|---|---|
| `string` | Text | `string(key)` | `string(key)` | `GetString(key)` |
| `integer` | A 32-bit whole number | `int(key)` (`getInt` from Java) | `integer(key)` | `GetInt(key)` |
| `bool` | `true` or `false` | `bool(key)` | `boolean(key)` | `GetBool(key)` |
| `choice` | One of `entryValues` | `string(key)` | `string(key)` | `GetString(key)` |
| `multi-select` | Some of `entryValues` | `strings(key)` | `strings(key)` | `GetStrings(key)` |
| `hidden` | Text, entered as a secret (see [Secrets](#secrets)) | `string(key)` | `string(key)` | `GetString(key)` |
| `bundle` | A group of settings | `bundle(key)` | `bundle(key)` in Dart, `values()` in TypeScript | `GetValues()` |
| `bundle_array` | A list of groups. Its one child is the `bundle` each item repeats | `bundles(key)` | `bundles(key)` in Dart, `values()` in TypeScript | `GetValues()` |

Bundles nest up to 4 levels deep.

When you upload a version (see [your apps](/management-api/guides/apps/)), the hub reads the
declaration from the APK. The form and the validation follow the newest version that declares
settings. `GET /v1/apps/{appId}/config-schema` returns that declaration:

```json
{
  "appId": "app_7h2m9q4x1c8v3k5n6p0r2s4t6w",
  "versionCode": 42,
  "restrictions": [
    { "key": "store_number", "type": "integer", "title": "Store number", "description": null,
      "default": 0, "entries": null, "entryValues": null, "children": null },
    { "key": "printer", "type": "bundle", "title": "Printer", "description": null,
      "default": null, "entries": null, "entryValues": null,
      "children": [
        { "key": "host", "type": "string", "title": "Host", "description": null,
          "default": null, "entries": null, "entryValues": null, "children": null }
      ] }
  ]
}
```

## Read the values

`OhrConfig` returns the value set for a key. If no value is set, it returns the default your XML
declares, and if there is none, the fallback you pass.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val server = OhrConfig.string("server_url")       // "https://pos.example.com" unless the fleet sets it
val store = OhrConfig.int("store_number")
val kiosk = OhrConfig.bool("kiosk_on_start")
val features = OhrConfig.strings("features")      // List<String>
val apiKey = OhrConfig.string("api_key")          // the secret, in the clear
val printer = OhrConfig.bundle("printer")         // Bundle?, null unless the fleet sets it
val lanes = OhrConfig.bundles("lanes").map { it.getString("name") }

// Every change while the app runs, as the new values:
OhrConfig.changes.collect { values -> reload(values) }
```

</TabItem>
<TabItem label="Java">

```java
import android.os.Bundle;

String server = OhrConfig.string("server_url");
int store = OhrConfig.getInt("store_number");     // int(...) in Kotlin
boolean kiosk = OhrConfig.bool("kiosk_on_start");
List<String> features = OhrConfig.strings("features");
Bundle printer = OhrConfig.bundle("printer");
List<Bundle> lanes = OhrConfig.bundles("lanes");

// Every change while the app runs, on the executor you pass; close it to stop:
Closeable watch = OhrConfig.listen(context.getMainExecutor(), values -> reload(values));
```

</TabItem>
<TabItem label="Dart">

```dart
final server = await OhrConfig.string('server_url');   // 'https://pos.example.com' unless the fleet sets it
final store = await OhrConfig.integer('store_number');
final kiosk = await OhrConfig.boolean('kiosk_on_start');
final features = await OhrConfig.strings('features');   // List<String>
final apiKey = await OhrConfig.string('api_key');       // the secret, in the clear
final printer = await OhrConfig.bundle('printer');      // a map, null unless the fleet sets it
final lanes = [for (final lane in await OhrConfig.bundles('lanes')) lane['name'] as String?];

// Every change while the app runs, as the new values; cancel the subscription to stop:
final watch = OhrConfig.changes.listen((values) => reload(values));
```

Bundles are `Map<String, Object?>`, bundle arrays lists of them.

</TabItem>
<TabItem label="TypeScript">

```ts
const server = await OhrConfig.string('server_url'); // 'https://pos.example.com' unless the fleet sets it
const store = await OhrConfig.integer('store_number');
const kiosk = await OhrConfig.boolean('kiosk_on_start');
const features = await OhrConfig.strings('features'); // string[]
const apiKey = await OhrConfig.string('api_key'); // the secret, in the clear

// Bundles are objects in values(), bundle arrays arrays of objects:
let config = await OhrConfig.values();
const printer = config['printer'] as { host?: string; port?: number } | undefined;
const lanes = ((config['lanes'] ?? []) as { name?: string }[]).map((lane) => lane.name);

// Every change while the app runs, as the new values; remove() to stop:
const watch = OhrConfig.addChangeListener((values) => {
  config = values;
});
```

</TabItem>
<TabItem label="C#">

```csharp
var server = OhrConfig.GetString("server_url");    // "https://pos.example.com" unless the fleet sets it
var store = OhrConfig.GetInt("store_number");
var kiosk = OhrConfig.GetBool("kiosk_on_start");
var features = OhrConfig.GetStrings("features");   // IReadOnlyList<string>
var apiKey = OhrConfig.GetString("api_key");       // the secret, in the clear

// Bundles are objects in GetValues(), bundle arrays arrays of objects:
var config = OhrConfig.GetValues();
var printerHost = (string?)config["printer"]?["host"];
var lanes = config["lanes"]?.AsArray().Select(lane => (string?)lane?["name"]).ToList() ?? [];

// Every change while the app runs, as the new values:
OhrConfig.Changed += (_, e) => config = e.Values;
```

The getters read Android's application restrictions directly, so they are synchronous. `Changed` is
raised on the synchronization context it was subscribed from (the UI thread in MAUI), otherwise on
the thread pool.

| Kotlin, Java | Dart | TypeScript | C# | |
|---|---|---|---|---|
| `values()` | `values()` | `values()` | `GetValues()` | Every value set: a `Bundle` in Kotlin and Java, a map, object or `JsonObject` in the others. Keys the fleet doesn't set are absent |
| `defaults()` | | | | The settings the app declares, as Android `RestrictionEntry` objects with their defaults |
| `isSet(key)` | `isSet(key)` | `isSet(key)` | `IsSet(key)` | Whether the fleet or the device sets `key` |
| `string`, `int`, `bool` | `string`, `integer`, `boolean` | `string`, `integer`, `boolean` | `GetString`, `GetInt`, `GetBool` | The value, else the declared default, else the fallback (`null`, `0`, `false` if you pass none). From Java, `int` is `getInt`; in Dart the fallback is a named argument, `fallback:` |
| `strings(key)` | `strings(key)` | `strings(key)` | `GetStrings(key)` | A `multi-select` value, else its declared default, else an empty list |
| `bundle(key)`, `bundles(key)` | `bundle(key)`, `bundles(key)` | | | A `bundle` or `bundle_array` value. Declared defaults don't apply: `null` or an empty list when not set |
| `changes` / `listen(executor, listener)` | `changes` | `addChangeListener(listener, onError?)` | `Changed` | The new values each time they change |

`OhrConfig` doesn't connect to the Agent, needs no fleet grant and can be called from any thread.
Changes arrive through Android's `ACTION_APPLICATION_RESTRICTIONS_CHANGED` broadcast, which is
sent only while your app runs. Read the values each time the app starts, and watch for changes
after that.

Managed configuration needs Agent 1061 or later. An older Agent doesn't set any values, so the
getters return your declared defaults. They don't throw.

## Set values

Values are set for one app, in a fleet or on one device:

| Level | Endpoints |
|---|---|
| A fleet, and the fleets below it | `GET`, `PUT`, `DELETE /v1/fleets/{fleetId}/apps/{appId}/config` |
| One device | `GET`, `PUT`, `DELETE /v1/devices/{deviceId}/apps/{appId}/config` |

`GET` needs `ViewSettings`; `PUT` and `DELETE` need `EditSettings`.

`PUT` replaces everything that level sets for the app. The hub sends the change to the devices
straight away.

<Tabs syncKey="lang">
<TabItem label="curl">

```sh
curl -X PUT https://api.ohrtech.net/v1/fleets/flt_2dn47a2xa58j1txv8m28spkmyb/apps/app_7h2m9q4x1c8v3k5n6p0r2s4t6w/config \
  -H "Authorization: Bearer $OHR_TOKEN" -H "Content-Type: application/json" \
  -d '{
    "values": {
      "server_url": "https://pos-east.example.com",
      "store_number": 42,
      "features": ["scan", "pay"],
      "printer": { "host": "printer-1.example.com", "port": 9100 },
      "lanes": [{ "name": "1" }, { "name": "2" }],
      "api_key": { "$secret": "sk_live_4f9c2e" }
    }
  }'
```

</TabItem>

The response shows what this level sets (`own`) and what the app gets (`effective`), with secrets
masked:

```json
{
  "appId": "app_7h2m9q4x1c8v3k5n6p0r2s4t6w",
  "fleetId": "flt_2dn47a2xa58j1txv8m28spkmyb",
  "deviceId": null,
  "own": { "store_number": 42, "api_key": { "$secret": "*" } },
  "effective": {
    "server_url": "https://pos.example.com",
    "store_number": 42,
    "api_key": { "$secret": "*" }
  },
  "problems": []
}
```

For a device, `fleetId` is the device's fleet, and `effective` is what the app on that device gets.
For a fleet, `effective` is what its devices get before their own overrides. `problems` lists the
effective values that don't match the app's newest declaration, such as a key that a newer version
dropped.

`DELETE` removes everything that level sets for the app, so the levels above apply again.

### Values

| Setting | JSON |
|---|---|
| `string`, `choice` | A string, up to 8,192 characters |
| `integer` | A whole number from -2147483648 to 2147483647 |
| `bool` | `true` or `false` |
| `multi-select` | A list of strings |
| `bundle` | An object of the bundle's keys |
| `bundle_array` | A list of objects, each with the item bundle's keys |
| `hidden` | A secret, `{"$secret": "…"}`, or a string |
| Any key | `null`: unset, so the app's default applies, whatever a parent fleet sets |

Keys are 1 to 128 of `A-Z a-z 0-9 _ . -`. Lists hold up to 256 items, values nest up to 4 levels
deep, and an app's configuration at one level is at most 64 KB.

When the app declares its settings, the hub checks values against them. Unknown keys, wrong
types and choices the app doesn't offer are refused with a 400, and nothing is stored:

```json
{
  "title": "Not this app's configuration",
  "status": 400,
  "detail": "store_number: a whole number. mode: one of customer, staff."
}
```

If no version of the app declares settings, the hub accepts any values of the shapes above.

### How levels combine

A device's app gets the values of its fleets from the top fleet down, then its own overrides. They
merge **per app and per key**: a fleet that sets `store_number` leaves the `server_url` its parent
sets alone. For each key, the deepest level that sets it wins: a child fleet over its parent, the
device over its fleets. A `bundle` or `bundle_array` value is one key, so a deeper level replaces it
as a whole.

`null` at any level unsets the key for that level and the ones below, until a level further down
sets it again.

### Secrets

Send a secret as `{"$secret": "value"}`. The hub seals it before storing it, and the API and the
portal only ever show it as `{"$secret": "*"}`. The hub opens it only to send it to the device,
and the app reads it as a plain string.

To keep a stored secret when you change other values, send `{"$secret": "*"}` back unchanged. If
nothing is stored for that key, the hub refuses it (400).

Secrets are allowed for `hidden` and `string` settings. The portal shows `hidden` settings as
password fields.

## In the portal

Open the fleet, go to its **Applications** tab and choose **Change** next to the app. Under
**Configuration** you get a form built from the settings the app declares, named with the version
it comes from. A setting this fleet doesn't set shows what it inherits from a parent fleet, or the
app's default. **Save configuration** stores the values and sends them to the fleet's devices.
**Stop configuring it in this fleet** does what `DELETE` does.

The portal sets values for fleets. To set one device's overrides, use
`PUT /v1/devices/{deviceId}/apps/{appId}/config`.

## On the device

The Agent sets the values as the app's application restrictions, typed by the settings the
installed APK declares: an `integer` setting becomes an `int`, a `multi-select` setting a `String[]`, a
`bundle` a `Bundle`, a `bundle_array` a `Bundle[]`. Android then sends the app
`ACTION_APPLICATION_RESTRICTIONS_CHANGED`.

- If the app isn't installed yet, it gets its values as soon as the hub installs it.
- When no level sets anything for the app any more, it goes back to its defaults.
- The device reports a fingerprint of the values it applied to the hub, never the values.
